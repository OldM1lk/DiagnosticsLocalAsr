# BL-010. Проверка GigaAM в Chrome, 25 ноября 2026

Docker-сборка включает страницу `bl010/` относительно базового пути приложения. Для стенда это `/DiagnosticsLocalAsr/bl010/`. Оригиналы выбираются на планшете через поле «Оригинал». Журналы JSONL с текстами остаются в локальной рабочей папке и исключены из Git.

**Решение для владельца.** GigaAM v3 CTC INT8 можно передавать на пробу на Huawei. Настольный Chrome исполнил весь граф в WASM и расшифровал обе записи. На длинной записи GigaAM лучше сохранила слова, однако потребовала заметно больше памяти при подготовке. Проба изолирована от основного приложения. Приёмка интеграции, физический планшет и полная серия T-08 открыты.

## Что именно запускалось

- Windows 10.0.26300, AMD Ryzen 7 5800H, доступная ОС физическая память 16,54 ГБ, Google Chrome 158.0.8127.88 headless. Код стенда в рабочем дереве OldM1lk/DiagnosticsLocalAsr, HEAD `7d8aeb832d6441b735770786b4f175e3999e29c5`. Для Whisper использован локальный собранный worker `asr-worker-VNNhtCwW.js`, SHA-256 `820638515e26de27e94b60960e2ded021b0a5c9b8ad848711385714bb5d37327`. Пробу обслуживал HTTP-сервер на loopback. Запрос к публичному HTTPS /DiagnosticsLocalAsr/ вернул 502. Источник образа и SHA в пилоте неизвестны. Перед публикацией нужны репозиторий и SHA сборочного задания либо сведения об образе от владельца размещения.
- Семейство включает v1, v2, v3 и multilingual. У v3 есть SSL, обычные CTC и RNN-T, а также E2E CTC и E2E RNN-T с пунктуацией и нормализацией. Для подсчёта сохранённых слов выбран однофайловый граф обычной русской CTC с посимвольным декодированием. У того же экспортёра FP32 CTC занимает 885,26 МБ, а RNN-T требует энкодер, декодер и joint. В карточке исходных весов и в LICENSE.txt экспорта указана MIT. При поставке весов приложить copyright и текст лицензии. [Авторы GigaAM](https://github.com/salute-developers/GigaAM), [карточка весов](https://huggingface.co/ai-sage/GigaAM-v3), [фиксированный экспорт и лицензия](https://huggingface.co/istupakov/gigaam-v3-onnx/tree/e8e041ef8dda01e744be2de526e6dd382243443d).
- GigaAM использует сторонний экспорт istupakov/gigaam-v3-onnx, ревизия `e8e041ef8dda01e744be2de526e6dd382243443d`. Граф `v3_ctc.int8.onnx` 224 721 181 байт, SHA-256 `ceb61454e2e1a2dec5872cbac1de0fe0a4271d1148f6b26b5bda53ff30a12acd`. Словарь `v3_vocab.txt` 198 байт. Формат входа — Float32 [1,64,T] и Int64 [1]. Моно 16 кГц, периодическое окно Hann длиной 320, шаг 160, без центрирования, спектр мощности, HTK mel от 0 до 8 кГц без нормировки, натуральный логарифм после ограничения значений [1e-9,1e9]. Выход log_probs [1,T′,34]. Берём максимум каждого кадра, объединяем соседние одинаковые индексы, удаляем blank 33. [Предобработка авторов](https://raw.githubusercontent.com/salute-developers/GigaAM/main/gigaam/preprocess.py).
- Из файла прочитан opset 17. В частности, граф содержит ConvInteger, MatMulInteger, DynamicQuantizeLinear, LayerNormalization, Range, Gather, Softmax и LogSoftmax. Совместимость всего графа проверена выполнением на двух длинах входа. Обе модели работали в выделенном worker, один поток, ONNX Runtime Web `1.22.0-dev.20250409-89f8206ba4`, только WASM. GigaAM использовала SIMD WASM объёмом 11,13 МБ.
- Whisper Tiny q8, onnx-community/whisper-tiny, ревизия `ff4177021cc41f7db950912b73ea4fdf7d01d8e7`, Transformers.js 3.8.1. Русский язык, transcribe, окно 30 с, перекрытие согласно параметру stride_length_s=5, do_sample=false. Модель с токенизатором и конфигурацией занимает 43,61 МБ. Полная конфигурация, SHA-256 аудио и список отданных ресурсов сохранены в [results.jsonl](results.jsonl).

Две публичные записи взрослого актёра из корпуса Langswap, одна и та же последовательность и байты в каждом прогоне. Подготовка включает инициализацию worker, получение ресурсов с loopback и создание сессии. Для каждой модели создан отдельный контекст Chrome. Повтор — новая страница в том же контексте с разрешённым HTTP-кэшем. Граф GigaAM и WASM браузер запросил повторно. Объём — сумма тел ответов локального сервера. Время ответа включает декодирование оригинала, подготовку признаков, вывод и получение текста. «Обе подряд» — от начала обработки первого файла до получения второго текста, без пауз оператора и записи в IndexedDB. Это очередь пробы. Время выгрузки очереди основного стенда до сохранения последнего результата на планшете ещё предстоит измерить.

Суммарный рабочий набор renderer-процессов отдельного тестового Chrome по трём снимкам (до подготовки / после / после двух файлов), в десятичных МБ. GigaAM — 160 / 929 / 714, при повторе 200 / 938 / 955. Whisper — 160 / 559 / 722, при повторе 265 / 586 / 685. Замер охватывает процессы целиком. Между снимками память могла достигать больших значений. Лимит вкладки Android и пиковое потребление на Huawei неизвестны.

## Как повторить

Из корня репозитория в PowerShell, с установленными зависимостями и Chrome. Для чистой рабочей копии сначала выполнить `npm ci`, `npm run prepare-resources`, установить `$env:APP_BASE_PATH='/DiagnosticsLocalAsr/'` и выполнить `npm run build`. Ниже используются локальные копии публичных WAV. Их контрольные суммы приведены в первой строке results.jsonl.

```powershell
$weights = Join-Path $env:TEMP 'bl010-gigaam-e8e041e'
New-Item -ItemType Directory -Force $weights | Out-Null
$origin = 'https://huggingface.co/istupakov/gigaam-v3-onnx/resolve/e8e041ef8dda01e744be2de526e6dd382243443d'
foreach ($name in 'LICENSE.txt','v3_vocab.txt','v3_ctc.yaml','v3_ctc.int8.onnx') {
  curl.exe -fLsS "$origin/$name" -o (Join-Path $weights $name)
  if ($LASTEXITCODE) { throw "Не удалось загрузить $name" }
}
$audio = 'C:/Users/Q/Documents/ChatGPT/Diagnostics/tools/local-asr/private-data'
node experiments/bl010/probe.mjs $weights "$audio/short.wav" "$audio/long.wav"
node experiments/bl010/check-retry.mjs $weights "$audio/short.wav"
node experiments/bl010/probe.mjs $weights --serve
```

Интерактивная проба открывается на http://127.0.0.1:5190/. Выбрать модель, нажать «Подготовить модель», выбрать оригинал, нажать «Распознать». Ошибка HTTP 503 при выдаче графа проверена в Chrome: на экране появилась «Ошибка GigaAM · failed to load external data file: /v3_ctc.int8.onnx». После восстановления доступа подготовка и повторное распознавание с тем же выбранным файлом прошли для GigaAM и Whisper. Веб-страница читает WAV локально. Список результатов пробы живёт до закрытия страницы. Для автоматического замера вывод JSONL можно перенаправить в локальный файл. Подсчёт ошибок повторяется командой `node experiments/bl010/score.mjs <журнал.jsonl> <metadata.csv>`.

## Согласование и приёмка на Huawei

1. **Сначала проба на устройстве.** При доступном Android Debug Bridge подключить Huawei MatePad SE 11″ 8/128 ГБ по USB с разрешённой отладкой, проверить устройство командой `adb devices`, затем выполнить `adb reverse tcp:5190 tcp:5190`. При работающем `--serve` открыть http://127.0.0.1:5190/ в Chrome планшета. WAV выбрать из файлов планшета. Зафиксировать фактическую версию Chrome (в старом отчёте 157.0.8103.78), ОС и состояние кэша. Для каждой модели на чистом профиле или после очистки данных **только тестового origin** подготовить модель, распознать short и long, перезагрузить и повторить. Отметить время, текст, отказ и выгрузку вкладки. USB нужен для выдачи статических ресурсов, вычисления выполняет планшет. HTTPS-размещение отдельным шагом требует сверки дерева.
2. **Предлагаемый выбор в основном стенде.** Выбирать Whisper/GigaAM до начала серии, фиксировать конфигурацию в серии и копировать её идентификатор в каждую попытку очереди. При парном сравнении запускать вторую серию на тех же идентификаторах оригиналов в том же порядке. Хранить неизменённый черновик и правку отдельно для каждой попытки в IndexedDB. В отчёте сохранять модель, SHA ревизии и графа, рантайм, число потоков, предобработку и декодер. В памяти держать один исполнитель.
3. **Отказ и повтор в интегрированной версии.** Сначала подготовить выбранную модель отдельной кнопкой. Заблокировать выдачу графа в чистой сессии. Проверить видимое имя модели и причину, доступность записи, сохранение оригинала и ожидающего задания. Восстановить доступ, повторить подготовку и задание, проверить идентификатор конфигурации в отчёте. Самостоятельно переключаться на другую модель при ошибке приложение не должно.
4. **Запись и восстановление в интегрированной версии.** На физическом Huawei начать распознавание длинного ответа. Пока идёт обработка, записать следующий короткий ответ, остановить запись и дождаться обеих расшифровок. Сохранить правку, перезагрузить страницу и воспроизвести оба оригинала, сверить тексты и правку, повторить распознавание одного оригинала. Замерить опустошение очереди до записи последнего текста. Отдельно проверить открытие стенда после перезагрузки без сети.
5. **Оценка правки.** Взрослому проверяющему дать одинаковый дословный критерий полноты, поочерёдно предъявлять черновики в уравновешенном порядке и засекать активную правку до подтверждения. Сохранить исходник, конечный текст и время для каждой пары. Две актёрские записи дают технический замер. Пилотные 166/142 с и 14,5% относятся к другому испытанию. Полное обследование, пять минут и экономия не менее 25% при равной полноте остаются в T-08.
